Subnetting, VLSM, CIDR and Supernetting

Last week a mask simply told us where the network part ends. This week we move that boundary deliberately. Moving it to the right (borrowing host bits) splits one network into subnets. Using different masks inside one network (VLSM) fits each subnet to its real size. Abandoning classes altogether gives CIDR. Moving the boundary to the left combines many networks into one route (supernetting / aggregation). These four techniques are how real IPv4 networks are designed and how the global routing table stays manageable.

Recap from Week 08Network = IP AND mask. Broadcast = network OR wildcard. Usable hosts = 2h − 2. Block size in the interesting octet = 256 − mask octet.

1. Why subnet?

Suppose a company owns 172.16.0.0/16: 65,534 hosts in one network. That is unworkable:

  • Broadcast domains. ARP, DHCP and other broadcasts reach every host. With thousands of hosts, broadcast traffic and CPU interruptions grow.
  • Organisation. Separate networks for departments, floors, buildings, servers, VoIP and guests make management easier.
  • Security. Traffic between subnets passes a router or firewall, where it can be filtered with ACLs.
  • Fault isolation. A broadcast storm or misconfiguration stays inside one subnet.
  • Address efficiency. Right-size each segment instead of wasting whole classful networks.

Subnetting (RFC 950) means taking some host bits and using them as a subnet ID. The address then has three parts:

| network prefix (given) | subnet ID (borrowed bits) | host ID (remaining) |
  172.16                 . 0000                       0000.00000000     (/16 → /20)

Outside the organisation the world still sees one network, 172.16.0.0/16. Inside, routers know the subnets.

2. Fixed-length subnetting (FLSM)

2.1 The two formulas

Borrowing s bits from the host part of a network with prefix p gives a new prefix p' = p + s, and with h = 32 − p':

Number of subnets2s
Usable hosts per subnet2h − 2

Every bit you borrow doubles the number of subnets and roughly halves the hosts per subnet. All subnets have the same size, hence "fixed length".

2.2 Worked example: 192.168.10.0/24 into 4 subnets

  1. We need 4 subnets, and 2s ≥ 4 gives s = 2, so the new prefix is /26 (mask 255.255.255.192).
  2. Host bits h = 6, so 26 − 2 = 62 hosts per subnet.
  3. Block size = 256 − 192 = 64, so subnets start at .0, .64, .128 and .192.
#Subnet ID bitsNetworkFirst hostLast hostBroadcast
000xxxxxx192.168.10.0/26.1.62.63
101xxxxxx192.168.10.64/26.65.126.127
210xxxxxx192.168.10.128/26.129.190.191
311xxxxxx192.168.10.192/26.193.254.255

2.3 The "magic number" (block size) method

  1. Find the interesting octet, the one where the mask is neither 255 nor 0.
  2. Magic number = 256 − mask value in that octet.
  3. Subnets start at multiples of the magic number in that octet. Octets to the right of it are 0 for the network address and 255 for the broadcast address.

Example: 172.16.0.0/20. The mask is 255.255.240.0, so the magic number is 16 in the 3rd octet. Subnets: 172.16.0.0, 172.16.16.0, 172.16.32.0, …, 172.16.240.0 (16 subnets). Each has 212 − 2 = 4094 hosts; for example 172.16.16.0/20 runs from 172.16.16.1 to 172.16.31.254, with broadcast 172.16.31.255.

FLSM splitter: divide a network into 2s equal subnets

2.4 Choosing the prefix from requirements

By number of subnets S: the smallest s with 2s ≥ S. By hosts per subnet H: the smallest h with 2h − 2 ≥ H, so p' = 32 − h. If both are given, check that s + h ≤ 32 − p; otherwise the requirements cannot be met with that block.

Class B 172.20.0.0/16, 50 subnets26 = 64 ≥ 50, so s = 6/22, 1022 hosts each

2.5 Subnet zero, the all-ones subnet and the old "2s − 2" formula

RFC 950 (1985) advised against using the first subnet (all-zero subnet ID) and the last (all-ones subnet ID). Subnet zero had the same network address as the classful network, and the all-ones subnet's broadcast equalled the classful directed broadcast. Classful routing protocols could not tell them apart. That is why older textbooks use 2s − 2 subnets. RFC 1878 (1995) and every modern CIDR-aware device use all 2s subnets. On Cisco IOS, ip subnet-zero has been on by default since 12.0. In exams, read the wording: "assume subnet zero is not used" means 2s − 2.

4. VLSM: Variable Length Subnet Masking

4.1 Why VLSM?

FLSM gives every subnet the same size. Real networks are uneven: one LAN with 100 PCs, another with 10 printers, and several router-to-router links that need exactly 2 addresses. With FLSM sized for the largest LAN, a point-to-point link would waste 124 of 126 addresses.

VLSM (RFC 1009) lets different subnets of the same network use different prefix lengths. Conceptually it is "subnetting a subnet": take one block and split it further.

4.2 The VLSM procedure: largest first

  1. List the requirements and add the router interface to each host count if it is not already included.
  2. Sort in descending order of size.
  3. For each requirement, choose the smallest block with 2h − 2 ≥ hosts (/30 or /31 for point-to-point links).
  4. Allocate blocks one after another from the start of the address space. Sorting guarantees that each block starts on a boundary that is a multiple of its size (alignment), so there are no overlaps or gaps.
  5. Record the network, mask, range and broadcast. Keep the unused space contiguous for growth.

Worked example: 192.168.1.0/24

Requirements: LAN-A 100 hosts, LAN-B 50, LAN-C 25, LAN-D 10, plus three WAN point-to-point links.

4.3 VLSM design pitfalls and good practice

  • Overlaps happen when blocks are allocated smallest-first or by hand without checking alignment. A /26 cannot start at .32; it must start at a multiple of 64.
  • Routing protocols must carry masks. VLSM needs classless protocols (RIPv2, OSPF, EIGRP, IS-IS, BGP). RIPv1 and IGRP do not send masks and break VLSM and discontiguous networks.
  • Discontiguous networks. If two subnets of 172.16.0.0/16 are separated by a different major network, automatic classful summarisation (old RIPv2/EIGRP defaults, auto-summary) advertises 172.16.0.0/16 from both sides and causes black holes. Use no auto-summary.
  • Plan for summarisation. Give each site or building a contiguous, power-of-two-aligned block (e.g. 10.1.0.0/16 for site 1, split internally) so that one summary route represents the whole site (§6).
  • Growth. Leave room next to each block so it can double without renumbering.
  • Point-to-point links: a /30 (2 usable) or /31 (RFC 3021). Router loopbacks: /32.

5. CIDR: Classless Inter-Domain Routing

5.1 What CIDR is

CIDR (RFC 1517–1520, 1993; updated by RFC 4632) abolished classes for allocation and routing:

  • An address block is described as a.b.c.d/n, where n (the prefix length) can be any value from 0 to 32. The first octet no longer implies anything.
  • Routers store and advertise prefix + length pairs, and routing protocols carry the mask.
  • Blocks can be allocated in any power-of-two size: an organisation needing 2,000 addresses receives a /21 (2,048) instead of a class B (65,536).

5.2 Hierarchical allocation

Addresses are delegated hierarchically: IANA → RIR (e.g. RIPE NCC for Europe) → LIR/ISP → customer. An ISP that receives 81.180.0.0/16 can hand out a /24 to company X, a /27 to company Y and so on, yet advertise only 81.180.0.0/16 to the rest of the Internet. This is "provider-aggregatable" (PA) space. "Provider-independent" (PI) space belongs to the customer and must be advertised separately.

                 Internet  ←  "send me anything matching 81.180.0.0/16"
                     │
                 ISP (81.180.0.0/16)
        ┌────────────┼──────────────┐
  81.180.4.0/24   81.180.5.0/27   81.180.64.0/18
   company X       company Y        large customer Z

5.3 CIDR and the global routing table

Before CIDR the backbone table was growing exponentially and class B space was nearly exhausted. CIDR slowed both problems by letting providers aggregate customer routes. Today the IPv4 BGP table still holds roughly a million prefixes. Growth comes from multihoming, PI space and deliberate deaggregation for traffic engineering (advertising more specific prefixes to steer inbound traffic) and DDoS mitigation. Most operators filter announcements longer than /24 for IPv4 (and /48 for IPv6), so /24 is the smallest globally routable block. Since IPv4 run-out, RIRs allocate tiny blocks (RIPE: a /24 from a waiting list), and a market transfers existing blocks.

6. Supernetting and route aggregation (summarisation)

6.1 Idea

Supernetting is the reverse of subnetting. Instead of borrowing host bits, you give network bits back, moving the mask boundary to the left, so that several contiguous networks are represented by one shorter prefix. In routing this is called route aggregation or summarisation. The benefits are smaller routing tables, less routing traffic, faster look-ups and stability: a flapping subnet inside the summary is invisible outside it.

6.2 Worked example: 4 × /24 → /22

Networks: 200.1.0.0/24, 200.1.1.0/24, 200.1.2.0/24, 200.1.3.0/24. Write the differing octet in binary:

200.1.000000|00.0     0
200.1.000000|01.0     1
200.1.000000|10.0     2
200.1.000000|11.0     3
       └─ common: 8+8+6 = 22 bits  →  summary 200.1.0.0/22  (mask 255.255.252.0)

Method: count the leading bits common to all networks; that is the summary prefix length. The summary address is those common bits followed by zeros.

6.3 Conditions for an exact aggregate

  1. The networks are contiguous, with no gaps.
  2. Their number is a power of 2 (2, 4, 8, …), assuming equal sizes.
  3. The first network is aligned: its relevant octet is a multiple of that count (for 4 × /24, the third octet is a multiple of 4).

Example of a problem: 200.1.1.0/24 – 200.1.4.0/24 (4 networks, but starting at 1, not aligned). The smallest single summary containing all of them is 200.1.0.0/21, which also includes 200.1.0.0 and 200.1.5.0–200.1.7.0 that you might not own. The exact minimal set is 200.1.1.0/24 + 200.1.2.0/23 + 200.1.4.0/24.

Route aggregator: single summary vs exact minimal set

6.4 Longest prefix match: why summaries and exceptions coexist

When several routing entries match a destination, a router chooses the one with the longest prefix, the most specific. This lets an ISP advertise an aggregate while a more specific route overrides part of it.

Classic case: ISP A owns 200.23.16.0/20 and advertises it. A customer with 200.23.18.0/23 moves to ISP B but keeps its addresses. ISP B advertises 200.23.18.0/23. Routers on the Internet keep both entries; traffic for 200.23.19.7 matches both, and the /23 wins, so it goes to ISP B.

Longest-prefix-match tester
Try 200.23.18.200, 200.23.20.1, 200.23.31.255, 8.8.8.8, 10.9.9.9

6.5 Operational aspects

  • Black-holing and the Null0 route. A router advertising a summary may receive traffic for addresses inside it that do not exist. Without a matching more-specific route it would follow its own default route back toward the sender, creating a loop. Routers therefore install a discard route for the summary (ip route 200.1.0.0 255.255.252.0 Null0; OSPF and EIGRP do it automatically).
  • Where to summarise. At hierarchy boundaries: OSPF area border routers (area X range), ASBRs (summary-address), BGP (aggregate-address … summary-only), EIGRP per interface (ip summary-address eigrp).
  • Cost of summarisation: loss of detail and possibly sub-optimal paths. If a component subnet fails, the summary is still advertised, so traffic is drawn in and dropped.
  • Hijack risk. A more specific announcement wins everywhere by LPM. Mis-announcements, such as the 2008 YouTube /24 incident, exploit exactly that. RPKI route-origin validation mitigates it.
  • Supernetting vs summarisation terminology. Strictly, "supernet" means a prefix shorter than the classful mask, e.g. 200.1.0.0/22 built from class C networks. Summarisation within a classful network (10.1.0.0/16 from many 10.1.x.0/24) is aggregation but not supernetting in the classful sense.

# Simple VLSM allocator (largest first)
def vlsm(block, reqs):
    free = ip.ip_network(block).network_address
    for name, h in sorted(reqs.items(), key=lambda kv: -kv[1]):
        bits = 2
        while 2**bits - 2 < h: bits += 1
        sub = ip.ip_network(f"{free}/{32-bits}")
        print(f"{name:8} {h:4} -> {sub}")
        free = sub.broadcast_address + 1

10. Summary and glossary

Key takeaways

  • Subnetting borrows host bits: 2s subnets of 2h − 2 hosts. Block size = 256 − interesting mask octet.
  • VLSM uses different masks inside one block. Allocate the largest first to keep blocks aligned and non-overlapping.
  • CIDR uses any prefix length; routes carry prefix + length; allocation is hierarchical.
  • Supernetting / aggregation combines contiguous, aligned, power-of-two groups into one shorter prefix.
  • Longest prefix match: the most specific route wins.
Subnet ID
The borrowed bits that number the subnets.
Block size / magic number
The distance between consecutive subnet addresses in the interesting octet.
FLSM / VLSM
Fixed / variable length subnet masks.
CIDR
Classless addressing and routing with arbitrary prefix lengths.
Aggregate / summary route
One prefix covering many more-specific prefixes.
Longest prefix match
The forwarding rule that picks the most specific matching entry.
Null0 / discard route
A route that drops traffic; protects against loops for summarised space.

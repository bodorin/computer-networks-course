1. The network layer: role and services

1.1 Where the network layer sits

The network layer is layer 3 of the OSI model. In TCP/IP it is called the Internet layer. Its job is to carry data from a source host to a destination host across many interconnected networks, possibly on the other side of the planet. The data link layer only moves frames across a single link or LAN; the network layer works end-to-end, across the whole path.

Layer (TCP/IP)PDU nameAddresses usedScope
Applicationmessagehostnames (e.g. www.example.com)process to process
Transportsegment (TCP) / datagram (UDP)port numbersprocess to process
Internet (network)packet / datagramIP addresses (logical)host to host, across networks
LinkframeMAC addresses (physical)one hop (one link / LAN)

Encapsulation: the sender's network layer takes a transport segment, adds an IP header (source IP, destination IP, TTL, protocol and so on) and passes the resulting IP packet to the link layer, which wraps it in a frame. Every router along the path removes the frame, looks at the IP header, decides where to send the packet next and wraps it in a new frame for the next link.

AnalogyAn IP packet is a letter with a destination postal address. The postal network (routers) moves it from sorting centre to sorting centre. Each local delivery van (a link) uses a different, local identifier, such as a van number or street slot. That local identifier plays the role of the MAC address.

1.2 The two key functions: forwarding and routing

Forwarding (data plane)A local action inside one router. When a packet arrives on an input interface, the router looks up its destination address in the forwarding table and moves the packet to the right output interface. It happens per packet, in nanoseconds, usually in hardware.
Routing (control plane)A network-wide process that decides the path packets take from source to destination. Routing algorithms and protocols (Week 11) compute and fill in the forwarding tables. It works on a timescale of seconds and is usually done in software.

Road-trip analogy: forwarding is choosing the right exit at one interchange; routing is planning the whole route from Bucharest to Vienna.

1.3 The service model: best-effort datagrams

The Internet's network layer offers a single, very simple best-effort service. It makes no guarantees that packets arrive, that they arrive in order, about delay or about bandwidth. Each packet is a datagram, routed on its own using its destination address; no connection is set up beforehand. Reliability, if needed, is added above, by TCP.

Datagram network (IP)Virtual-circuit network (ATM, X.25, Frame Relay; partially MPLS)

Why the Internet chose datagrams: simplicity at the core (the "dumb network, smart end-hosts" principle, also called the end-to-end argument), robustness to failures, and easy interconnection of very different link technologies ("IP over everything").

1.4 Data plane, control plane and SDN

In traditional routers the control plane is distributed: every router runs routing protocols (OSPF, BGP and others) and computes its own table. In Software-Defined Networking (SDN) the control plane is logically centralised in a controller, which installs flow tables into simple switches through a southbound API such as OpenFlow. OpenFlow generalises forwarding into match + action: a switch can match on many header fields (MAC, IP, ports, VLAN) and then forward, drop, rewrite or send the packet to the controller. Destination-based IP forwarding is the special case that matches only on the destination IP prefix.

Other network-layer services that exist in principle but are not part of Internet best effort: guaranteed delivery, bounded delay, in-order delivery, minimum bandwidth, security. IntServ/RSVP and DiffServ (the DSCP field, Week 10) add QoS on top of IP.

Why both? Routers cannot keep an entry for every MAC address in the world; flat addresses do not aggregate. Hierarchical IP addresses let one routing entry such as "all of 81.180.0.0/16 goes that way" cover thousands of hosts. Inside the final LAN, though, frames must still be delivered to a specific NIC, so the MAC is needed for the last hop. ARP (Week 10) maps IP addresses to MAC addresses.

Key factAlong a path, the source and destination IP addresses stay the same (unless NAT intervenes). The MAC addresses change at every hop.

2. The IPv4 address

2.1 Structure: 32 bits, 4 octets

An IPv4 address is a 32-bit number. For humans it is written in dotted-decimal notation: four octets (8-bit groups), each written in decimal from 0 to 255 and separated by dots.

Binary : 11000000 10101000 00000001 00001010
Decimal:   192   .  168   .   1    .  10      →  192.168.1.10

The total number of IPv4 addresses is 232 = 4,294,967,296. The pool held by IANA was exhausted in February 2011, and the Regional Internet Registries (RIPE NCC for Europe, ARIN, APNIC, LACNIC, AFRINIC) have since run out of their ordinary pools. That shortage is the main driver of NAT, CIDR and IPv6.

2.2 Binary refresher: positional weights

Each bit position in an octet has a weight, a power of 2:

bit76543210
weight1286432168421

Binary → decimal: add the weights of the 1-bits: 10101000 = 128 + 32 + 8 = 168.
Decimal → binary (subtraction method): 200 ≥ 128, so write 1, leaving 72; 72 ≥ 64, 1, leaving 8; 8 < 32, 0; 8 < 16, 0; 8 ≥ 8, 1, leaving 0; then 0, 0, 0. Result: 11001000.

Patterns worth memorising (they appear in every mask)10000000=128, 11000000=192, 11100000=224, 11110000=240, 11111000=248, 11111100=252, 11111110=254, 11111111=255.

2.3 Network part and host part

Every IPv4 address is split into two parts:

  • Network ID (prefix), the leftmost bits: identifies the network (the "street"). All hosts on the same network share it.
  • Host ID, the remaining bits: identifies the interface within that network (the "house number").

Where the split falls is given either by the class (historically) or by the subnet mask / prefix length (today). Note that an IP address identifies an interface, not a host: a router with three interfaces has three IP addresses, and a laptop with Wi-Fi and Ethernet has two.

3. Classful addressing (classes A–E)

3.1 The five classes

The original IPv4 design (RFC 791, 1981) divided the address space into classes. The class is identified by the first bits of the first octet:

ClassLeading bitsFirst-octet rangeDefault mask (prefix)Network / host bitsNumber of networksHosts per networkIntended use
A00–127 (1–126 usable)255.0.0.0 (/8)8 / 2427 = 128 (126 usable)224 − 2 = 16,777,214very large organisations
B10128–191255.255.0.0 (/16)16 / 16214 = 16,384216 − 2 = 65,534medium and large organisations
C110192–223255.255.255.0 (/24)24 / 8221 = 2,097,15228 − 2 = 254small networks
D1110224–239nonen/an/an/amulticast groups
E1111240–255nonen/an/an/areserved / experimental

Why only 7 network bits in class A? The leading 0 is fixed, leaving 7 free bits. Likewise B has 16 − 2 = 14 free network bits and C has 24 − 3 = 21.

Networks 0.x.x.x and 127.x.x.x are reserved ("this network" and loopback), so class A has 126 usable networks.

3.3 Why classful addressing failed

  • Huge waste (granularity problem). A company needing 2,000 addresses was too big for a C (254) and got a B (65,534), wasting about 97% of it. Class B was being exhausted by the early 1990s.
  • Routing-table explosion. Organisations needing more than 254 addresses but too small for a B received several C networks, and each needed its own entry in every backbone router.
  • No internal structure. A class B network of 65k hosts in one broadcast domain is unmanageable.

Fixes, in historical order: subnetting (RFC 950, 1985), VLSM (RFC 1009, 1987), CIDR (RFC 1519, 1993; now RFC 4632), private addresses + NAT (RFC 1918, 1996), and in the long run IPv6. You will study subnetting, VLSM and CIDR in Week 09.

3.4 What "class" still means today

Since CIDR, Internet routing is classless: the prefix length travels with every route and the first octet means nothing to a modern router. Classes survive in vocabulary ("a class C-sized /24"), in a few legacy behaviours (some OS installers derive a default mask from the first octet, and RIPv1 and IGRP are classful protocols that do not send masks) and in exams. The class D range is still multicast (224.0.0.0/4) and class E (240.0.0.0/4) is still reserved; there were proposals to reclaim 240/4 for unicast, but many stacks refuse it.

4. Special and reserved IPv4 addresses

4.1 Network address and broadcast address

Inside every network (or subnet), two host-ID values are reserved:

  • Network address: host bits all 0. It names the network itself and appears in routing tables. Example: 192.168.1.0 for 192.168.1.0/24.
  • Directed broadcast: host bits all 1. A packet sent to it reaches all hosts on that network. Example: 192.168.1.255. Routers do not forward directed broadcasts by default (RFC 2644), which defends against "smurf" amplification attacks.

This is why the host count is 2h − 2, where h is the number of host bits.

Other special forms:

  • Limited broadcast 255.255.255.255: all hosts on this link, never forwarded by routers. DHCP uses it.
  • 0.0.0.0: "this host / unspecified". It is the source address used by a DHCP client that has no address yet; in a server socket it means "listen on all interfaces", and in a routing table 0.0.0.0/0 is the default route.
  • Loopback 127.0.0.0/8, usually 127.0.0.1 (localhost): packets never leave the host.

4.2 Private addresses (RFC 1918)

Three blocks are reserved for private networks. Anyone can use them internally without asking a registry, but they are not routable on the public Internet. To reach the Internet, a router performs NAT (Network Address Translation, Week 10).

4.4 Subtleties

  • /31 point-to-point links (RFC 3021). On a link with exactly two ends, a network and a broadcast address are useless. A /31 therefore gives 2 usable addresses, saving half the space compared with /30. Most router operating systems support it.
  • /32 host routes. A single address, used for loopback interfaces on routers (router IDs, BGP peering) and for host routes.
  • All-zeros and all-ones subnets. Historically (RFC 950) the first and last subnet of a subnetted network were avoided because of ambiguity with the classful network and broadcast. RFC 1878 and modern practice allow them (Cisco: ip subnet-zero, the default since IOS 12.0).
  • Multicast addresses map to MAC addresses 01:00:5E + the low 23 bits of the IP address. That makes 32 IP groups share each MAC, a 5-bit ambiguity.

5. The subnet mask

5.1 Definition and notations

A subnet mask is a 32-bit value with 1s in the network-part positions and 0s in the host-part positions. The ones must be contiguous and on the left: 11111111.11111111.11110000.00000000 is valid; 11111111.00000000.11111111.00000000 is not.

There are two equivalent notations:

  • Dotted decimal: 255.255.240.0
  • Prefix length (slash / CIDR notation): /20, the number of 1-bits. So 10.1.0.0 255.255.240.0 is the same as 10.1.0.0/20.

Default masks: class A 255.0.0.0 (/8), class B 255.255.0.0 (/16), class C 255.255.255.0 (/24).

Valid octet values in a mask: 0, 128, 192, 224, 240, 248, 252, 254, 255, and an octet can be less than 255 only if every octet after it is 0.

5.2 The bitwise AND: extracting the network address

A device finds the network an address belongs to by applying a bitwise AND between the address and the mask: 1 AND 1 = 1; every other combination gives 0. The mask "keeps" the network bits and "zeroes" the host bits.

IP     172.16.45.200   10101100.00010000.00101101.11001000
Mask   255.255.240.0   11111111.11111111.11110000.00000000
AND    ─────────────   ───────────────────────────────────
Network 172.16.32.0    10101100.00010000.00100000.00000000
Broadcast = network OR (NOT mask) = 172.16.47.255
AND visualiser: network, broadcast and host range

5.3 Counting hosts, and the "interesting octet" shortcut

With prefix length p, the number of host bits is h = 32 − p:

  • Total addresses in the block: 2h
  • Usable host addresses: 2h − 2 (minus the network and broadcast addresses). Exceptions: /31 has 2 and /32 has 1.
  • First usable host = network + 1; last usable host = broadcast − 1.

Mental shortcut. Find the interesting octet, the one where the mask is neither 255 nor 0. The block size is 256 − (mask octet). Network boundaries in that octet are multiples of the block size.
Example: 172.16.45.200 /20 has mask octet 240 in octet 3, so block = 16. Multiples of 16: …, 32, 48, … and 45 falls in [32, 48). Network = 172.16.32.0; broadcast = 172.16.47.255.

5.4 Same network or not? How a host decides

Before sending, a host ANDs its own address with its mask and the destination address with the same mask:

  • If the results are equal, the destination is on-link. The host ARPs for the destination's MAC and delivers the frame directly.
  • If not, the destination is remote. The host sends the frame to the default gateway (router) MAC; the IP destination remains the final host.
Direct delivery or default gateway?
Mask mismatchIf two hosts on the same LAN are configured with different masks, communication can become one-directional: A thinks B is local, B thinks A is remote and sends to the gateway. This is a classic troubleshooting case.

5.5 Wildcard (inverse) masks and non-contiguous masks

A wildcard mask is the bitwise NOT of a subnet mask: 255.255.240.0 ↔ 0.0.15.255. Here 0 means "must match" and 1 means "don't care". Cisco ACLs and the OSPF network command use wildcards, e.g. network 10.1.32.0 0.0.15.255 area 0. Unlike subnet masks, wildcards in ACLs may be non-contiguous; 0.0.0.254 matches all odd or all even hosts. Non-contiguous subnet masks were technically allowed by early RFCs but are forbidden in CIDR practice because they break longest-prefix matching.

Wildcard = 255.255.255.255 − mask, octet by octet. Broadcast = network OR wildcard.

6. The Java InetAddress class

6.1 Overview

java.net.InetAddress represents an IP address, optionally with an associated hostname. It is the building block for sockets (Socket, ServerSocket, DatagramSocket), which all take an InetAddress or a hostname that is resolved into one.

  • It has no public constructor. Instances come from static factory methods such as getByName, which may perform DNS look-ups.
  • It has two subclasses: Inet4Address (32 bits) and Inet6Address (128 bits). The factory returns the right one.
  • Objects are immutable and can be compared with equals(), which compares the address bytes and not the hostname.
  • Methods that look up names throw UnknownHostException, a subclass of IOException.

6.3 Example 1: resolving names

import java.net.*;

public class Lookup {
    public static void main(String[] args) {
        String host = args.length > 0 ? args[0] : "www.example.com";
        try {
            InetAddress a = InetAddress.getByName(host);          // one address (DNS A/AAAA)
            System.out.println("Name   : " + a.getHostName());
            System.out.println("Address: " + a.getHostAddress());
            System.out.println("Type   : " + (a instanceof Inet4Address ? "IPv4" : "IPv6"));

            for (InetAddress x : InetAddress.getAllByName(host))      // all addresses
                System.out.println("  -> " + x);                 // prints "hostname/literal"

            InetAddress me = InetAddress.getLocalHost();
            System.out.println("Local host: " + me);
            System.out.println("Loopback  : " + InetAddress.getLoopbackAddress());
        } catch (UnknownHostException e) {
            System.err.println("Cannot resolve " + host + ": " + e.getMessage());
        }
    }
}

Compile and run: javac Lookup.java && java Lookup www.google.com. Note that toString() prints hostname/literal; the hostname part is empty if none is known.

6.4 Example 2: classifying addresses and computing the network address

import java.net.*;

public class AddrInfo {
    // Java bytes are SIGNED (-128..127): mask with 0xFF to get 0..255
    static int toInt(byte[] b) {
        return ((b[0] & 0xFF) << 24) | ((b[1] & 0xFF) << 16) | ((b[2] & 0xFF) << 8) | (b[3] & 0xFF);
    }
    static String toDotted(int v) {
        return ((v >>> 24) & 255) + "." + ((v >>> 16) & 255) + "." + ((v >>> 8) & 255) + "." + (v & 255);
    }
    static char classOf(int firstOctet) {
        if (firstOctet < 128) return 'A'; if (firstOctet < 192) return 'B';
        if (firstOctet < 224) return 'C'; if (firstOctet < 240) return 'D'; return 'E';
    }
    public static void main(String[] args) throws Exception {
        InetAddress a = InetAddress.getByName("172.16.45.200");  // literal: no DNS query
        int prefix = 20;
        int ip   = toInt(a.getAddress());
        int mask = prefix == 0 ? 0 : 0xFFFFFFFF << (32 - prefix);   // careful: shift by 32 is a no-op in Java!
        int net  = ip & mask, bc = net | ~mask;
        System.out.println("Class      : " + classOf(a.getAddress()[0] & 0xFF));
        System.out.println("Private?   : " + a.isSiteLocalAddress());
        System.out.println("Loopback?  : " + a.isLoopbackAddress());
        System.out.println("Mask       : " + toDotted(mask));
        System.out.println("Network    : " + toDotted(net));
        System.out.println("Broadcast  : " + toDotted(bc));
        System.out.println("Hosts      : " + ((1L << (32 - prefix)) - 2));

        // Building an address from bytes (values > 127 need a cast)
        byte[] raw = { (byte) 192, (byte) 168, 1, 10 };
        InetAddress b = InetAddress.getByAddress(raw);
        System.out.println(b.getHostAddress() + "  same as literal? " + b.equals(InetAddress.getByName("192.168.1.10")));
    }
}

6.6 Advanced: caching, interfaces and pitfalls

  • DNS caching. The JVM caches successful look-ups (security property networkaddress.cache.ttl; the default is 30 s without a security manager) and failed ones (networkaddress.cache.negative.ttl, 10 s by default). Long-running services may need to tune this when DNS records change, e.g. in cloud failover.
  • Blocking look-ups. getByName blocks the calling thread. In GUI or high-concurrency code, call it off the main thread. Since Java 18 the resolver is pluggable (InetAddressResolverProvider, JEP 418).
  • Literal vs name. getByName("10.0.0.300") is not a valid literal, so Java tries DNS and fails with UnknownHostException. ofLiteral (Java 22) fails fast with IllegalArgumentException instead.
  • isSiteLocalAddress() covers exactly 10/8, 172.16/12 and 192.168/16 for IPv4 (and the deprecated fec0::/10 for IPv6). It does not include 100.64/10 or the IPv6 ULAs fc00::/7.
  • isReachable() is unreliable through firewalls; a false result does not prove the host is down.
  • Preferring IPv4 or IPv6: the system properties java.net.preferIPv4Stack and java.net.preferIPv6Addresses.

S3. Valid masks?
Which of these are valid subnet masks? 255.255.255.192 · 255.255.0.255 · 255.224.0.0 · 255.255.250.0 · 0.0.0.0 · 255.255.255.255
Show solution Valid: 255.255.255.192 (/26), 255.224.0.0 (/11), 0.0.0.0 (/0, the default route), 255.255.255.255 (/32, a host).

S4. Network, broadcast, range
For 10.45.170.33/19 find the mask, the network, the broadcast, the first and last host and the number of hosts.
Show solution /19 gives mask 255.255.224.0. The interesting octet is the third (224), so the block size is 32. Multiples of 32: 160, 192, and 170 lies in [160, 192).

S5. Same network?
Host A = 192.168.5.62/27 and host B = 192.168.5.66/27. Can they talk directly? What if the mask is /25?
Show solution /27 has block 32. A is in 192.168.5.32–63; B is in 192.168.5.64–95. Different networks, so traffic goes through a router.
/25 has block 128. Both are in 192.168.5.0–127, the same network, so delivery is direct (ARP).
S6. Troubleshooting
A PC shows IP 169.254.77.12, mask 255.255.0.0 and no default gateway. It cannot browse. What happened and what do you check?
Show solution The PC self-assigned an APIPA address because it got no DHCP reply. Check: the cable or Wi-Fi association, the switch port or VLAN, that the DHCP server is up and its pool is not exhausted, and the DHCP relay (ip helper-address) if the server is on another subnet. Then run ipconfig /renew (Windows) or sudo dhclient -r && sudo dhclient (Linux).
S7. Design reasoning
An ISP has to number 1,000 customer point-to-point links. How many addresses does it need with /30 and with /31? Why do some engineers still prefer /30?
Show solution /30: 4 addresses per link, 4000 in total (a /20 holds 4096). /31: 2 per link, 2000 in total (fits in a /21 = 2048), a 50% saving.
Some prefer /30 because a few legacy devices and operating systems do not support RFC 3021, and some monitoring tools treat .0 or .255-like addresses specially.
S8. Java signed-byte bug
A student writes int first = addr.getAddress()[0]; and for 192.168.1.1 gets −64. Explain and fix. Also explain why 0xFFFFFFFF << (32 - prefix) fails for prefix = 0.
Show solution Java byte is signed. 192 = 0xC0, which as a signed byte is −64. Fix: int first = addr.getAddress()[0] & 0xFF;.
In Java (and JavaScript), shift distances on int are taken modulo 32, so x << 32 equals x. For /0 the expression gives 0xFFFFFFFF instead of 0. Handle /0 as a special case, or use long arithmetic.

11. Summary, glossary and further reading

Key takeaways

  • The network layer moves packets host-to-host across networks. Forwarding is local and per packet; routing is network-wide and computes the paths.
  • IP addresses are logical and hierarchical (network + host); MAC addresses are physical and flat. The IPs stay the same end-to-end while the MACs change at every hop.
  • IPv4 = 32 bits = 4 octets in dotted decimal. Classes A (0…), B (10…), C (110…), D multicast, E reserved.
  • The mask marks the network bits. Network = IP AND mask; broadcast = network OR NOT mask; hosts = 2h − 2.
  • Private: 10/8, 172.16/12, 192.168/16. Loopback: 127/8. APIPA: 169.254/16.
  • Java InetAddress: factory methods, DNS resolution, address predicates.

Glossary

Octet
A group of 8 bits; an IPv4 address has four.
Prefix length
The number of leading 1-bits in the mask, written /n.
Network address
The address with all host bits 0; it identifies the network.
Directed broadcast
The address with all host bits 1; it reaches all hosts of that network.
Default gateway
The router to which a host sends packets for off-link destinations.
APIPA
Automatic Private IP Addressing: a self-assigned 169.254.x.x address.
NAT
Network Address Translation: rewriting private addresses into public ones at the network edge.
Data plane / control plane
Per-packet forwarding vs. the computation of routes.
Wildcard mask
The inverse of a mask; used in ACLs and OSPF.

The Internet Protocol: IPv4 and IPv6

So far we have treated IP addresses as numbers to compute with. This week we open the IP packet itself: what is in the header, how a datagram is fragmented when a link cannot carry it, and which helper protocols (ICMP, ARP, DHCP, NAT) make IPv4 work. Then we move to IPv6: why it exists, how its 128-bit addresses are written and structured, how hosts configure themselves, how its header differs, and how the Internet is transitioning from IPv4.

1. IP: the protocol in one page

IP (Internet Protocol) is the only protocol that every Internet host and router must run, the "narrow waist" of the hourglass. Many applications and transports sit above it and many link technologies below it. Its properties:

  • Connectionless: each datagram is handled independently.
  • Unreliable / best effort: datagrams can be lost, duplicated, delayed or reordered. IP gives no acknowledgements and no retransmissions.
  • Responsibilities: addressing (source and destination IP), forwarding hop by hop, adapting to link MTUs (fragmentation in IPv4), loop protection (TTL / hop limit), header error detection (IPv4 checksum) and demultiplexing to the right upper protocol (Protocol / Next Header field).
      HTTP  DNS  SMTP  SSH  QUIC …
          TCP      UDP     ICMP
     ──────────── IP (v4 / v6) ────────────   ← narrow waist
     Ethernet  Wi-Fi  4G/5G  fibre  DSL …

2.3 TTL in practice: traceroute

traceroute (tracert on Windows) exploits TTL. It sends probes with TTL = 1, 2, 3, … The router where TTL reaches 0 discards the probe and returns ICMP Time Exceeded (type 11), revealing its address. The destination finally answers with ICMP Echo Reply (Windows probes) or ICMP Port Unreachable (Unix UDP probes to high ports). Default initial TTLs differ by operating system (Linux/macOS 64, Windows 128, many routers 255), which is why a received TTL hints at the sender's OS and distance.

2.4 Computing the header checksum

Algorithm (RFC 1071): set the checksum field to 0, add all 16-bit words of the header using one's-complement addition (add any carry out of bit 15 back into the sum), then invert all the bits. A receiver adds all words including the checksum; the result must be 0xFFFF. Routers update it incrementally after decrementing the TTL (RFC 1624). IPv6 dropped the header checksum altogether: link layers (CRC) and transports already check for errors, and removing it speeds up forwarding.

3. Fragmentation and reassembly (IPv4)

3.1 MTU

Every link technology has a Maximum Transmission Unit, the largest IP packet a frame can carry: Ethernet 1500 bytes, PPPoE 1492, jumbo frames 9000, the IPv6 minimum 1280, and 576 bytes is the minimum every IPv4 host must accept. If a router must forward a datagram larger than the next link's MTU, IPv4 lets it fragment the datagram into smaller IP packets. They are reassembled only at the destination host, never by intermediate routers.

3.2 The rules

  1. Each fragment gets a copy of the IP header (with possibly modified options) and the same Identification value.
  2. Data per fragment (except the last) must be a multiple of 8 bytes: max data = ⌊(MTU − header) / 8⌋ × 8.
  3. Fragment Offset = position of the fragment's first data byte ÷ 8.
  4. MF = 1 on every fragment except the last; the last has MF = 0 (and offset ≠ 0).
  5. If DF = 1 and fragmentation is needed, the router drops the packet and returns ICMP "Fragmentation Needed" (type 3, code 4) with the next-hop MTU.

Example (Kurose): a 4000-byte datagram (20 header + 3980 data) on a link with MTU 1500. Max data per fragment = 1480 (1480/8 = 185).

3.3 Why fragmentation is avoided: PMTUD

  • Cost: losing one fragment loses the whole datagram; reassembly consumes memory at the receiver (an attack surface: teardrop, fragment floods); firewalls and NAT cannot see port numbers in non-first fragments.
  • Path MTU Discovery (RFC 1191): TCP sends with DF = 1. When a router returns "Fragmentation Needed, next-hop MTU = X", the sender lowers its segment size. Black-hole problem: if firewalls block that ICMP message, large packets silently vanish; connections hang after the handshake. Workarounds: MSS clamping on routers (ip tcp adjust-mss 1452 on PPPoE) and PLPMTUD (RFC 4821 / 8899), which probes without relying on ICMP.
  • IPv6: routers never fragment. Only the source may, using a Fragment extension header, so PMTUD (via ICMPv6 Packet Too Big) is mandatory, and the minimum link MTU is 1280.

4. Helper protocols of IPv4: ICMP, ARP, DHCP, NAT

4.1 ICMP: Internet Control Message Protocol

ICMP (RFC 792) carries error and diagnostic messages inside IP packets (Protocol = 1). It is considered part of IP.

TypeNameUsed by / meaning
0 / 8Echo Reply / Echo Requestping
3Destination Unreachablecodes: 0 net, 1 host, 3 port, 4 fragmentation needed with DF set, 13 administratively prohibited
5Redirect"use a better gateway on this link"
11Time ExceededTTL reached 0 (traceroute) or reassembly timeout

ICMP errors are never sent in response to ICMP errors, broadcasts or non-first fragments, which avoids storms.

4.2 ARP: Address Resolution Protocol

To deliver an IP packet on an Ethernet LAN, the sender needs the next hop's MAC address. ARP (RFC 826) resolves IPv4 address to MAC:

  1. Host A checks its ARP cache (arp -a).
  2. If there is no entry, it broadcasts (destination MAC FF:FF:FF:FF:FF:FF) an ARP Request: "Who has 192.168.1.20? Tell 192.168.1.10."
  3. The owner replies with a unicast ARP Reply: "192.168.1.20 is at 3C:52:82:…".
  4. A caches the mapping (typically for minutes) and sends the frame.

For off-link destinations, A ARPs for the default gateway, not for the remote host. Advanced: gratuitous ARP (announcing one's own address, detecting duplicates, failover); ARP spoofing / poisoning as a man-in-the-middle attack, mitigated by Dynamic ARP Inspection. IPv6 replaces ARP with NDP (§9).

4.3 DHCP: automatic configuration

DHCP (RFC 2131, UDP ports 67/68) gives a host its IP address, mask, default gateway, DNS servers and lease time. The four-message exchange is DORA: Discover (broadcast from 0.0.0.0 to 255.255.255.255) → Offer → Request → Acknowledge. A router configured as a DHCP relay (ip helper-address) forwards these broadcasts to a server on another subnet.

4.4 NAT and PAT

NAT (RFC 3022) rewrites addresses at the boundary between a private network and the Internet. Its common form, PAT / NAPT ("NAT overload"), maps many private (IP, port) pairs onto one public IP with different ports, keeping a translation table. Static NAT maps one private address to one public address and is used to publish servers; dynamic NAT draws from a pool of public addresses.

Side effects of NATIt breaks the end-to-end principle: inbound connections need port forwarding; protocols that carry IP addresses in their payload (FTP active mode, SIP) need application-level gateways; it adds per-flow state. NAT is not a security mechanism in itself, although it hides internal addressing. CGNAT (100.64.0.0/10) adds a second NAT layer at the ISP.

5. IPv6: motivation

  • Address exhaustion: 232 addresses are not enough for billions of phones, IoT devices and cloud services. IPv6 has 2128 ≈ 3.4 × 1038.
  • No need for NAT: every device can have a globally unique address, restoring end-to-end connectivity (firewalls still filter).
  • Simpler, fixed 40-byte header: faster processing; no checksum; no fragmentation by routers.
  • Autoconfiguration (SLAAC), built-in multicast, no broadcast, better support for mobility and hierarchical aggregation.
  • IPsec was originally mandatory and is now recommended; it is available in both versions.

Adoption: depending on the day, roughly 45–50% of users reaching Google do so over IPv6 (Google's public statistics), with large variation by country and network. Mobile networks and big content providers lead.

6. IPv6 address representation

6.1 Format

128 bits are written as 8 groups ("hextets") of 4 hexadecimal digits (16 bits each), separated by colons:

2001:0db8:0000:0000:0000:ff00:0042:8329

Two compression rules

  1. Leading zeros in any group may be omitted: 0db8 → db8, 0000 → 0, 0042 → 42.
  2. One run of consecutive all-zero groups may be replaced by ::, only once per address (otherwise the length would be ambiguous).
2001:0db8:0000:0000:0000:ff00:0042:8329
→ 2001:db8:0:0:0:ff00:42:8329          (rule 1)
→ 2001:db8::ff00:42:8329               (rule 2)

The prefix is written as in CIDR: 2001:db8:acad:1::/64. With URLs and ports use brackets: http://[2001:db8::1]:8080/.

6.2 Canonical form (RFC 5952)

  • Lowercase hex digits; leading zeros removed.
  • :: must replace the longest run of zero groups (if tied, the first) and must not be used for a single 0 group: 2001:db8:0:1:1:1:1:1, not 2001:db8::1:1:1:1:1.
IPv6 expander / compressor (RFC 5952)
Try: fe80::1 · ::1 · :: · 2001:db8:0:0:1:0:0:1 · ff02::1:ff3c:4d5e · ::ffff:192.0.2.128

7. IPv6 address types

IPv6 has three kinds of address: unicast (one interface), multicast (a group) and anycast (the nearest member of a group, using unicast format). There is no broadcast; the all-nodes multicast address ff02::1 plays that role. An IPv6 interface normally has several addresses at once: always a link-local, plus one or more global or ULA addresses, plus joined multicast groups.

  • A typical site receives a /48 (or a /56 for homes). Each LAN is a /64, which SLAAC requires.
  • Subnetting is usually done by counting in the 16-bit subnet ID, in hex: 2001:db8:acad:0000::/64, :0001::/64, …, :ffff::/64. No mask arithmetic on octets is needed; work on nibble boundaries (multiples of 4 bits) for readability.
  • There is no "−2": IPv6 has no broadcast address; the all-zeros interface ID is the Subnet-Router anycast address.

8. Interface identifiers: EUI-64, privacy and stable addresses

8.1 Modified EUI-64

  1. Take the 48-bit MAC, e.g. 00:1A:2B:3C:4D:5E.
  2. Split it in half and insert FF:FE in the middle: 00:1A:2B:FF:FE:3C:4D:5E.
  3. Invert bit 7 (the universal/local "U/L" bit, value 0x02) of the first byte: 00 becomes 02.
  4. Result: interface ID 021a:2bff:fe3c:4d5e, so the link-local address is fe80::21a:2bff:fe3c:4d5e.
EUI-64 generator

8.2 Why EUI-64 is no longer the default for hosts

An EUI-64 interface ID embeds the MAC address, so the same device can be tracked across networks. Modern operating systems use temporary (privacy) addresses (RFC 8981, formerly RFC 4941), random IDs that change daily, for outgoing connections. For their stable address they use semantically opaque stable IDs (RFC 7217: a hash of the prefix, the interface and a secret). Routers and servers usually get manually configured or EUI-64 addresses.

9.3 Extension-header chain

Each header's Next Header field names the following header, forming a chain that ends with the transport header. The recommended order (RFC 8200): Hop-by-Hop Options (0), Destination Options (60), Routing (43), Fragment (44), Authentication Header (51), ESP (50), Destination Options, then upper layer (6 TCP, 17 UDP, 58 ICMPv6). Only Hop-by-Hop is examined by every router. In practice packets with extension headers are often dropped on the Internet (RFC 7872), which is a real deployment issue. Segment Routing over IPv6 (SRv6) uses the Routing header.

[IPv6 hdr NH=43] → [Routing hdr NH=44] → [Fragment hdr NH=6] → [TCP segment]

9.4 ICMPv6 and Neighbor Discovery (NDP)

ICMPv6 (RFC 4443, Next Header 58) is essential in IPv6; blocking it breaks the network. It carries errors (Destination Unreachable, Packet Too Big, Time Exceeded), echo, and the Neighbor Discovery Protocol (RFC 4861):

Message (type)PurposeReplaces in IPv4

9.5 Address configuration: SLAAC, stateless and stateful DHCPv6

  1. The host builds its link-local address (fe80:: + interface ID) and runs DAD (Duplicate Address Detection): an NS from :: to the solicited-node group of its own address; silence means the address is unique.
  2. It sends an RS and receives an RA with the prefix (e.g. 2001:db8:acad:1::/64) and flags.
  3. SLAAC (A flag): the host forms prefix + interface ID itself; the default gateway is the router's link-local address.
  4. O flag (stateless DHCPv6): the address comes from SLAAC, while extra information (DNS) comes from DHCPv6. DNS can also come from the RA itself (RDNSS option, RFC 8106).
  5. M flag (stateful DHCPv6): addresses come from a DHCPv6 server (UDP 546/547). Note that DHCPv6 does not provide a default gateway; that always comes from RAs.

10. Transition from IPv4 to IPv6

IPv4 and IPv6 are not compatible on the wire: an IPv4-only host cannot talk to an IPv6-only host directly. Three families of techniques exist:

  • Dual stack: devices run both protocols at once. This is the most common and simplest approach, but it still needs IPv4 addresses. With DNS, clients receive A and AAAA records and prefer IPv6 ("Happy Eyeballs", RFC 8305, races both).
  • Tunnelling: IPv6 packets are carried inside IPv4 packets (Protocol 41) across IPv4-only parts of the network: manual 6in4, GRE, the obsolete automatic 6to4 and Teredo (over UDP for hosts behind NAT), and 6rd (ISP-operated).
  • Translation: NAT64 + DNS64 let IPv6-only clients reach IPv4-only servers. DNS64 synthesises AAAA records 64:ff9b::<IPv4> and NAT64 translates the packets. 464XLAT (RFC 6877, used by many mobile operators) adds a client-side translator (CLAT) so IPv4-only apps still work on an IPv6-only network.

10.1 Comparison and trends

11. Seminar: worked problems

S1. Header reading
An IPv4 header starts with 45 00 05 DC 1C 46 40 00 3F 06 …. Find the version, header length, total length, DF/MF flags, offset, TTL and protocol.
Show solution 45: version 4, IHL 5, so 20 bytes. 05DC = 1500 total. ID 0x1C46. 4000 = 0100 0000 0000 0000: DF = 1, MF = 0, offset 0. TTL 0x3F = 63. Protocol 06 = TCP.
S2. Compress / expand
(a) Compress 2001:0db8:0000:0000:0000:0000:0000:0001 and fe80:0000:0000:0000:0202:b3ff:fe1e:8329. (b) Expand 2001:db8::8:800:200c:417a and ::1. (c) Is 2001:db8::1::2 valid?
Show solution (a) 2001:db8::1 · fe80::202:b3ff:fe1e:8329. (b) 2001:0db8:0000:0000:0008:0800:200c:417a · 0000:…:0001 (7 zero groups, then 0001). (c) Invalid: "::" may appear only once.
S3. Fragmentation
A 2400-byte datagram (header 20) must cross a link with MTU 820. Give each fragment's total length, offset and MF. If it then crosses a link with MTU 500, what happens to the first fragment?
Show solution Max data = ⌊800/8⌋×8 = 800. Data 2380 = 800 + 800 + 780. Fragment 1: length 820, offset 0, MF 1. Fragment 2: 820, offset 100, MF 1. Fragment 3: 800, offset 200, MF 0.
At MTU 500: max data 480. The first fragment's 800 bytes split into 480 (offset 0, MF 1) + 320 (offset 60, MF 1, because the original fragment had MF = 1). Reassembly still happens only at the destination.
S4. EUI-64 and solicited-node
MAC 2C:54:91:88:C9:E3, prefix 2001:db8:cafe:10::/64. Give the global and link-local addresses and the solicited-node multicast group.
Show solution 2C = 00101100, flipping bit 0x02 gives 00101110 = 2E. IID 2e54:91ff:fe88:c9e3. Global 2001:db8:cafe:10:2e54:91ff:fe88:c9e3; link-local fe80::2e54:91ff:fe88:c9e3; solicited-node ff02::1:ff88:c9e3.
S5. IPv6 subnetting
A university receives 2001:db8:4400::/40 and wants a /48 per faculty and /64 LANs. How many faculties and LANs per faculty? Give the 3rd faculty's prefix and its 10th LAN.
Show solution /40 → /48 gives 28 = 256 faculties; /48 → /64 gives 65,536 LANs each. The faculties are 2001:db8:4400::/48, 4401, 4402 …, so the 3rd (index 2) is 2001:db8:4402::/48. Its 10th LAN (index 9) is 2001:db8:4402:9::/64.
S6. Checksum by hand
Verify that the checksum of header 4500 0073 0000 4000 4011 ???? c0a8 0001 c0a8 00c7 is b861.
Show solution Sum: 4500+0073+0000+4000+4011+c0a8+0001+c0a8+00c7 = 0x2479C. Fold the carry: 0x479C + 0x2 = 0x479E. One's complement: 0xFFFF − 0x479E = 0xB861 ✔. Check with the calculator in §2.4.
S7. PMTUD black hole
Users behind a PPPoE link (MTU 1492) can open small web pages but large pages stall. ping with size 1472 + DF fails, while 1464 succeeds. Explain and give two fixes.
Show solution 1472 + 28 (IP + ICMP headers) = 1500 > 1492, while 1464 + 28 = 1492 fits. TCP uses MSS 1460 (for 1500), and the "Fragmentation Needed" ICMP is blocked somewhere, so large segments vanish: a PMTUD black hole. Fixes: MSS clamping to 1452 on the PPPoE router; allow ICMP type 3 code 4 through firewalls; or lower the client MTU.
S8. Transition design
A mobile operator wants to stop allocating IPv4 to phones. Which mechanism lets an IPv4-only app (one that uses a hard-coded IPv4 literal) keep working? Sketch the packet path.
Show solution 464XLAT. The CLAT on the phone translates IPv4 to IPv6 (stateless, RFC 7915) using the NAT64 prefix. The packet crosses the IPv6-only network to the operator's PLAT (a stateful NAT64), which translates it to IPv4 with a shared public address. Plain NAT64/DNS64 alone fails for literals because no DNS query happens.

14. Summary and glossary

Key takeaways

  • IPv4 header: 20–60 B; key fields TTL, Protocol, checksum, ID/flags/offset, addresses.
  • Fragmentation: data in multiples of 8, offset in 8-byte units, MF on all but the last; reassembly at the destination; avoided by PMTUD.
  • ICMP gives diagnostics, ARP maps IP to MAC, DHCP configures hosts, NAT/PAT maps private to public.
  • IPv6: 128 bits, 8 hextets, rules "drop leading zeros" and "one ::". Types: GUA 2000::/3, link-local fe80::/10, ULA fc00::/7, multicast ff00::/8; no broadcast.
  • Fixed 40-byte header, extension headers, no router fragmentation, no checksum. NDP replaces ARP; SLAAC/DHCPv6 configure hosts.
  • Transition: dual stack, tunnels, translation (NAT64/DNS64, 464XLAT).
MTU
Largest IP packet a link can carry.
PMTUD
Path MTU Discovery, using DF plus ICMP feedback.
PAT / NAPT
Many-to-one NAT distinguished by ports.
Hextet
A 16-bit group of an IPv6 address.
EUI-64
Interface ID derived from a MAC with FFFE inserted and the U/L bit flipped.
SLAAC
Stateless Address Autoconfiguration from router advertisements.
DAD
Duplicate Address Detection.
Dual stack
Running IPv4 and IPv6 simultaneously.

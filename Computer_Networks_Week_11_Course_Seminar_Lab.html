Routing in IP Networks

In Weeks 08–10 we built addresses and packets, and we saw that a router forwards each packet by looking up its destination in a table. This week answers the remaining question: who fills in that table, and how? We start with the routing table and the rules a router uses to choose between routes. Then come static routes and the classification of dynamic routing algorithms, followed by the two classic algorithms, Dijkstra and Bellman-Ford, which you can run step by step on this page. Finally we see how they become real protocols (distance-vector RIP, link-state OSPF) and how the Internet is held together by the exterior protocol BGP.

1. Fundamental principles of routing

1.1 Routing vs forwarding (recap)

Routing is the process of determining the path packets take from source to destination. It runs in the router's control plane and produces the routing table (RIB, Routing Information Base). The best entries are copied into the forwarding table (FIB), which the data plane consults for every packet. IP routing is hop-by-hop: each router decides only the next hop, trusting the next router to continue.

  • Directly connected (C) routes appear automatically when an interface has an address and is up. Local (L) are /32 routes for the router's own addresses.
  • Static (S) routes are configured by hand; dynamic routes (O, R, D, B) are learned from routing protocols.
  • The default route 0.0.0.0/0 (IPv6 ::/0) matches everything. It is the gateway of last resort, used when nothing more specific matches. Without one, unmatched packets are dropped and an ICMP Destination Unreachable is returned.

1.3 How a route is chosen: three tie-breakers in order

  1. Longest prefix match (per packet, in the FIB). The most specific matching prefix wins, regardless of where it came from.
  2. Administrative distance (when building the RIB). If several sources offer the same prefix, the one with the lowest AD (most trusted) is installed.
  3. Metric (within one protocol). Among routes from the same protocol to the same prefix, the lowest metric wins. Equal metrics mean ECMP (Equal-Cost Multi-Path) load sharing.

2. Static routing

2.1 Concept, advantages and disadvantages

A static route is entered manually by the administrator: "to reach network X, send to next hop Y (or out of interface Z)".

AdvantagesNo protocol overhead (CPU, bandwidth); predictable and secure (nothing is advertised); simple for small or stub networks; full control of the path.
DisadvantagesDoes not adapt to failures (unless a floating backup exists); laborious and error-prone at scale; every change must be made on many routers.

Typical uses: stub networks (one way out), a default route toward the ISP, backup routes, and routes to networks that should not be advertised.

2.2 Configuration (Cisco IOS and Linux)

2.3 Subtleties

  • Recursive look-up: a next-hop route requires a second look-up to find how to reach the next hop. If that next hop becomes reachable only through the default route, the route may stay "up" while traffic is black-holed. Use fully specified routes or IP SLA / BFD tracking (ip route … track 1).
  • Exit-interface-only routes on Ethernet make the router ARP for every destination (proxy ARP needed), so avoid them.
  • Static routes can be redistributed into dynamic protocols (redistribute static); a default route can be originated in OSPF with default-information originate.

3. Dynamic routing and the classification of routing algorithms

3.1 What dynamic routing protocols do

A dynamic routing protocol lets routers exchange information automatically, discover remote networks, compute the best paths and react to topology changes. Its components are: data structures (neighbour table, topology database, routing table), an algorithm (Bellman-Ford, Dijkstra, DUAL, path-vector) and messages (hellos, updates, acknowledgements).

  • Convergence: the state in which all routers have consistent, correct tables after a change. Fast convergence is the main quality criterion, since loops and black holes occur during it.
  • Metric: the value used to compare paths: hop count (RIP), cost derived from bandwidth (OSPF), bandwidth plus delay (EIGRP), or policy attributes (BGP).

3.3 The graph abstraction

A network is modelled as a graph G = (N, E): N = routers (nodes), E = links (edges), with a cost c(x,y) for each edge (∞ if there is no direct link). The cost of a path is the sum of its link costs. The routing problem is to find the least-cost path between each pair of nodes. Costs may represent the inverse of bandwidth, delay, money or administrative preference; with all costs equal to 1, least-cost means fewest hops.

4. Classic routing algorithms: Dijkstra and Bellman-Ford

4.1 Dijkstra's algorithm (link-state, global)

Each router knows the whole topology (from flooded link-state advertisements) and computes least-cost paths from itself to all other nodes. After the k-th iteration the least-cost paths to k destinations are known.

Initialisation:
  N' = {u}
  for all nodes v:
     if v adjacent to u then D(v) = c(u,v), p(v) = u
     else D(v) = ∞
Loop:
  find w not in N' such that D(w) is a minimum
  add w to N'
  for each neighbour v of w not in N':
     D(v) = min( D(v), D(w) + c(w,v) )      // if improved, p(v) = w
until N' = N

Notation: D(v) is the current least cost from the source to v; p(v) is the predecessor of v on that path; N' is the set of nodes whose least-cost path is final.

4.2 Dijkstra: complexity, correctness and oscillations

  • Complexity: with n nodes, the simple version checks all remaining nodes each iteration, n + (n−1) + … = O(n²). With a binary heap it is O((|E| + |N|) log |N|).
  • Requires non-negative costs. With negative edges a node fixed early could later be improved, so greedy finalisation is wrong. Real routing costs are positive.
  • Oscillations with load-sensitive costs: if link cost equals the traffic carried, all routers move to the currently cheapest path, making it expensive, and then all move back. Remedies: load-insensitive costs, or desynchronising the SPF runs (random timers). Routers synchronising their periodic messages is a known self-organisation phenomenon (Floyd and Jacobson).
  • Message complexity of link-state: O(|N|·|E|) messages to flood all LSAs.

4.3 Bellman-Ford (distance vector, decentralised)

The Bellman-Ford equation (dynamic programming): the least cost from x to y is the minimum, over all neighbours v of x, of the cost to reach v plus v's least cost to y:

dx(y) = minv { c(x,v) + dv(y) }The neighbour v that achieves the minimum is the next hop in x's forwarding table.

Centralised version: start with d(source) = 0 and everything else ∞, then relax every edge |N| − 1 times. A further round that still improves something reveals a negative cycle. Complexity: O(|N|·|E|).

Distributed version (distance-vector routing): each node keeps its distance vector Dx = [Dx(y) for all y] and the vectors last received from its neighbours. It is iterative (runs until no changes), asynchronous (no lock-step needed) and distributed (each node talks only to neighbours):

at each node x:
  wait for (change in a local link cost  OR  a distance vector from a neighbour)
  recompute  D_x(y) = min_v { c(x,v) + D_v(y) }   for every destination y
  if D_x changed for any destination:
       send D_x to all neighbours

5. Distance-vector routing protocols

5.1 RIP: Routing Information Protocol

  • Metric: hop count; maximum 15; 16 = infinity (unreachable). This limits RIP to small networks.
  • Updates: the whole routing table is sent to neighbours every 30 s (RIPv1 by broadcast; RIPv2 to multicast 224.0.0.9; RIPng to ff02::9), using UDP port 520 (RIPng: 521).
  • Timers: invalid 180 s (route marked unreachable if no update arrives), hold-down 180 s (Cisco), flush 240 s (route removed).
  • RIPv1 is classful with no authentication. RIPv2 (RFC 2453) is classless, carries masks and next hop, supports MD5 authentication and route tags. RIPng (RFC 2080) is for IPv6.

5.2 The count-to-infinity problem and its remedies

"Good news travels fast, bad news travels slowly." Take the linear network A–B–C (each link cost 1). B reaches A in 1 hop and C in 2 via B. If link A–B fails, B no longer has a direct path. But C still advertises "A at distance 2", so B believes it can reach A through C at 3. C then updates to 4 via B, B to 5 via C, and so on until 16 = ∞. Meanwhile packets for A loop between B and C until their TTL expires.

RemedyHow it works
Maximum metric (infinity = 16)Bounds the counting so it ends eventually.
Split horizonNever advertise a route back out of the interface through which it was learned. C does not tell B about A.
Poison reverseAdvertise it back, but with metric ∞. Explicit, so faster than waiting for timeouts.

5.3 Advanced distance vector: EIGRP and DUAL

EIGRP (Cisco, published as RFC 7868) avoids loops with the DUAL algorithm. It keeps a successor (the best path) and feasible successors: neighbours whose reported distance is less than the current feasible distance (the feasibility condition), which guarantees they are loop-free. When the successor fails, a feasible successor is used immediately with no recomputation. If none exists, the router sends queries (DUAL "active" state). EIGRP sends partial, bounded updates instead of periodic full tables. Its metric is 256 × (107/min BWkbps + Σ delaytens of µs) with default K values.

6. Link-state routing protocols

6.1 How link-state routing works

  1. Discover neighbours with Hello packets (OSPF: every 10 s on Ethernet; dead interval 40 s).
  2. Measure the cost of each link.
  3. Build a link-state packet (LSA/LSP) describing "me, my links, their costs", with a sequence number and an age.
  4. Flood it reliably to all routers in the area. Each router forwards new LSAs out of all its other interfaces.
  5. Every router assembles the identical link-state database (LSDB), a map of the area.
  6. Each router runs Dijkstra (SPF) with itself as the root and installs the results in its routing table.

Updates are sent only when something changes (plus periodic refreshes, every 30 minutes in OSPF), which means less steady-state traffic than RIP and fast convergence.

6.2 OSPF

  • Open standard: OSPFv2 (RFC 2328) for IPv4, OSPFv3 (RFC 5340) for IPv6. It runs directly over IP (protocol 89) using multicast 224.0.0.5 (all SPF routers) and 224.0.0.6 (DR/BDR).
  • Packet types: Hello, Database Description (DBD), Link-State Request (LSR), Link-State Update (LSU), Link-State Ack (LSAck).
  • Neighbour states: Down → Init → 2-Way → ExStart → Exchange → Loading → Full.
  • Cost = reference bandwidth / interface bandwidth, default reference 100 Mbps, minimum 1. With the default, FastEthernet, GigabitEthernet and 10G all cost 1. Fix it with auto-cost reference-bandwidth 100000 (in Mbps) on all routers.
  • Router ID: a 32-bit identifier. It is set manually, or else taken from the highest loopback address, or else the highest active interface address.
  • DR/BDR on multi-access networks (Ethernet): routers form full adjacencies only with the Designated Router and its Backup, which reduces adjacencies from n(n−1)/2 to about 2n. The highest interface priority wins, then the highest router ID.
  • Authentication (MD5 or SHA), equal-cost multipath, and classless operation with VLSM and summarisation.

6.3 Hierarchy: OSPF areas and LSA types

Large OSPF domains are divided into areas to limit flooding and SPF computation. Area 0 is the backbone, and every other area must attach to it. ABRs (Area Border Routers) connect areas and summarise between them; ASBRs inject external routes. Main LSA types: 1 Router, 2 Network (produced by the DR), 3 Summary (ABR, inter-area), 4 ASBR-summary, 5 AS-External, 7 NSSA-External. Stub, totally stubby and NSSA areas filter external and summary LSAs to keep small routers' databases small. Inside an area routing is link-state; between areas OSPF actually behaves like a distance-vector protocol, which is why all areas must hang off area 0 (to avoid loops).

IS-IS is a similar link-state protocol originally designed for OSI. It runs directly over layer 2 and uses Level-1/Level-2 routers instead of areas around a backbone. It is popular in large ISP networks because it is protocol-agnostic (IPv4 and IPv6 in one instance) and scales well.

7. Interior and exterior routing: autonomous systems and BGP

7.1 Why two levels of routing?

The Internet has hundreds of millions of routers. One flat routing domain is impossible because of scale (tables and flooding) and administrative autonomy (each organisation wants to run its network its own way and hide internal details). The solution is hierarchical routing:

  • An Autonomous System (AS) is a set of routers under one administration with one routing policy, identified by an ASN: 16-bit (1–64511 public, 64512–65534 private) or 32-bit (RFC 6793). Examples: AS15169 Google, AS2614 RoEduNet.
  • Intra-AS routing (IGP): RIP, OSPF, IS-IS, EIGRP. They optimise performance, and all routers in the AS run the same IGP.
  • Inter-AS routing (EGP): BGP-4 (RFC 4271) is the de facto standard, "the glue that holds the Internet together". It is driven by policy (who may carry whose traffic), not just by performance.
  • Gateway routers (border routers) sit at the edge of an AS and run both an IGP and BGP.

7.2 BGP essentials

  • Path-vector protocol: advertisements carry a prefix plus attributes, notably the AS_PATH, the list of ASes the advertisement has passed through. A router rejects any route containing its own ASN, which gives loop prevention.
  • Sessions run over TCP port 179 between configured peers. eBGP sessions connect different ASes; iBGP sessions distribute external routes inside an AS (full mesh or route reflectors). Messages: OPEN, UPDATE, KEEPALIVE, NOTIFICATION.
  • NEXT_HOP: the address of the border router that starts the path. Inside the AS the IGP is used to reach it, which links BGP and the IGP (hot-potato routing).
  • Policy: import and export filters. A customer AS does not provide transit between its two providers; providers give customers full transit. Business relationships (customer, peer, provider) decide what is advertised.

7.3 BGP best-path selection

When a router learns several paths to the same prefix, it applies these rules in order (simplified; vendors add steps):

  1. Highest Weight (Cisco-local).
  2. Highest LOCAL_PREF (set by the AS's policy, applied AS-wide).
  3. Locally originated routes.
  4. Shortest AS_PATH.
  5. Lowest ORIGIN (IGP < EGP < incomplete).
  6. Lowest MED (a hint from a neighbouring AS about which entry point to use).
  7. eBGP over iBGP.
  8. Lowest IGP metric to the NEXT_HOP (hot-potato routing: get rid of the packet as soon as possible).
  9. Oldest eBGP route, then lowest router ID.
BGP best-path chooser (simplified)

Security: BGP trusts its peers by default, which makes prefix hijacks and route leaks possible. Mitigations include prefix filtering (IRR), RPKI route-origin validation and, in progress, ASPA and BGPsec.

S7. OSPF cost design
Paths R1→R4: (a) R1–R2–R4 over two 1 Gbps links; (b) R1–R3–R4 over 10 Gbps then 100 Mbps. With the default reference bandwidth, which path is chosen? With reference 100,000 Mbps?
Show solution Default (100): (a) 1 + 1 = 2; (b) 1 + 1 = 2, a tie, so ECMP over both. The 100 Mbps link is treated like 1 Gbps, which is bad. With 100,000: (a) 100 + 100 = 200; (b) 10 + 1000 = 1010, so path (a) is chosen, which is correct.
S8. BGP policy
AS 65010 is multihomed to ISP-A (AS 100) and ISP-B (AS 200). It wants all outbound traffic to use ISP-A unless ISP-A fails, and it must never become a transit AS between A and B. Which attributes and filters do you use?
Show solution Outbound preference: set a higher LOCAL_PREF (e.g. 200) on routes learned from ISP-A. Inbound preference (optional): prepend 65010 several times on announcements to ISP-B so its AS_PATH looks longer. No transit: an outbound filter to each ISP that advertises only the AS's own prefixes (e.g. an AS_PATH filter ^$, meaning locally originated routes only).

11. Summary of the week and of Chapter 4

Key takeaways

  • The routing table holds prefix, next hop, interface, AD and metric. Forwarding uses LPM; RIB selection uses AD, then metric.
  • Static routing is simple and controlled but does not adapt; it suits stubs, defaults and backups (floating routes).
  • Algorithms: global link-state (Dijkstra, O(n²)) vs decentralised distance-vector (Bellman-Ford, dx(y) = minv{c(x,v) + dv(y)}).
  • RIP: hops ≤ 15, 30 s updates, count-to-infinity mitigated by split horizon, poison reverse, hold-down and triggered updates.
  • OSPF: link state, cost = reference / bandwidth, hellos, LSDB, SPF, areas with backbone area 0, DR/BDR.
  • IGP inside an AS (performance) vs EGP between ASes: BGP is a path-vector, policy-driven protocol with AS_PATH loop prevention.
Chapter 4 in one picture Addresses (IPv4/IPv6, masks, subnets, CIDR) say where a host is → the IP protocol carries packets with those addresses, hop by hop, best effort → routing algorithms and protocols build the tables so each router knows the next hop → aggregation (CIDR) and hierarchy (areas, ASes) let the whole thing scale to the global Internet.
RIB / FIB
Routing Information Base (control plane) / Forwarding Information Base (data plane).
Administrative distance
The trustworthiness of a route source; lower is better.
Floating static route
A static route with a higher AD, used as a backup.
Convergence
The state in which all routers agree on correct routes.
Split horizon / poison reverse
Loop-prevention rules of distance-vector protocols.
LSA / LSDB / SPF
Link-state advertisement / database / shortest-path-first computation.
Autonomous system (AS)
A routing domain under one administration and policy, identified by an ASN.
Path vector
Distance vector plus the full AS path, used by BGP.
Hot-potato routing
Choosing the exit with the lowest internal cost.
